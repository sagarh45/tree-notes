Tree Basics

What a tree is, the vocabulary every later topic uses, and how a general tree is stored in memory.

Syllabus: Definition and terminology of trees.

1.1Definition

Definition (write this in the exam)

A tree is a finite set of one or more nodes such that (i) there is one specially designated node called the root, and (ii) the remaining nodes are partitioned into n ≥ 0 disjoint sets T1, T2, …, Tn, where each set is itself a tree. T1 … Tn are called the subtrees of the root.

The definition is recursive: a tree is a root plus smaller trees. That is why almost every tree algorithm is written with recursion. A tree is a non-linear, hierarchical data structure: one element can have many successors, but only one predecessor.

A tree with n nodes has exactly n − 1 edges, no cycles, and exactly one path between any two nodes.

Every node except the root has exactly one parent, and each parent link is one edge. So n nodes give n − 1 edges. If you add one more edge you create a cycle; if you remove one you split the tree in two.

Tree vs. graph, linear vs. non-linear

Arrays, stacks, queues and linked lists are linear: every element has at most one next element, so the data sits on a single line. A tree is non-linear: one node can lead to several nodes, so the data spreads out in levels. A tree is a special kind of graph.

1.3Representing a general tree in memory

A general tree allows any number of children, so a node cannot have a fixed number of pointer fields without waste. There are two standard ways to store it.

(a) Fixed k child pointers per node

Give each node k pointer fields, where k is the degree of the tree. With n nodes there are nk pointer fields, but only n − 1 are used (one per edge). So n(k − 1) + 1 fields hold NULL. For k = 3 and n = 13 that is 27 wasted fields out of 39.

(b) Left-child right-sibling (LCRS)

Every node keeps just two pointers: left → its first child and right → its next sibling. Any general tree becomes a binary tree this way. This is the reason we study binary trees in such detail: they can represent every tree.

struct gnode {
    char data;
    struct gnode *firstChild;    /* left pointer  */
    struct gnode *nextSibling;   /* right pointer */
};
Conversion rule: keep the edge from each parent to its left-most child, delete the parent's edges to all other children, and link the siblings left to right. Then rotate the picture 45° clockwise.

1.4Where trees are used

File systems

Folders inside folders. The drive is the root and files are leaves.

Database indexes

B-trees and B+ trees keep millions of keys a few disk reads away.

Compilers

Expression and syntax trees store operator precedence in their shape.

Searching and sorting

BST and AVL trees give O(log n) search, insert and delete.

HTML / XML

The DOM is a tree: every tag is nested inside exactly one parent tag.

Decision making

Decision trees and game trees; each level is one decision or move.

Key points to remember

  • A tree is a non-linear, hierarchical structure: one root, every other node has exactly one parent, no cycles.
  • n nodes ⇒ n − 1 edges, and exactly one path between any two nodes.
  • Degree counts children; depth/level counts edges down from the root; height counts edges up from the deepest leaf.
  • State your convention: root at level 0, height in edges (leaf = 0).
  • A general tree is stored as a binary tree using left-child, right-sibling.

Binary Tree

Trees where every node has at most two children. Covers the seven types, formulas, array and linked storage, recursive and non-recursive traversals, rebuilding a tree from traversals, and insert, search and delete.

Syllabus: Binary tree · traversal (pre-order, in-order, post-order) · linked implementation · insert, search, delete.

2.1Definition

Definition

A binary tree is a finite set of nodes that is either empty, or consists of a root and two disjoint binary trees called the left subtree and the right subtree.

There are two differences from a general tree. A binary tree can be empty, and the order of children matters: a left child and a right child are different positions even when a node has only one child.

2.2Types of binary tree

Each type below has four parts: the definition to write in the exam, a description of what it looks like and where it is used, the formulas it satisfies, and a test to decide whether a given tree is of that type. A C function for each test is at the end of this section.

1. Full binary tree also: strict, proper, 2-tree

Definition
A binary tree in which every node has either 0 or 2 children.
Description
No node has exactly one child. Levels need not be filled and leaves can be at different depths. An expression tree with only binary operators is always full: every operator has two operands and every operand is a leaf.
Formulas
With i internal nodes and L leaves: L = i + 1, n = 2i + 1 = 2L − 1. So n is always odd. For height h: 2h + 1 ≤ n ≤ 2h+1 − 1.
How to check
Visit every node. If any node has exactly one child, it is not full. Quick count test: n must equal 2L − 1.

2. Complete binary tree

Definition
A binary tree in which every level except possibly the last is completely filled, and all nodes of the last level are as far left as possible.
Description
If you number the nodes level by level (0, 1, 2, …), a complete tree uses positions 0 to n − 1 with no gap. That is why it can be stored in an array without waste, and why heaps are complete trees. At most one node has a single child, and that child is a left child.
Formulas
h = ⌊log2 n⌋ · 2h ≤ n ≤ 2h+1 − 1 · leaves = ⌈n/2⌉ · internal nodes = ⌊n/2⌋ · node i (0-based) has a left child only if 2i + 1 < n.
How to check
Index test: give the root position 0 and each child position 2i + 1 or 2i + 2. The tree is complete if every position is less than n. Level-order test: walk the tree with a queue; once you meet the first missing child, every node after that must be a leaf.

3. Perfect binary tree

Definition
A binary tree in which every internal node has exactly two children and all leaves are at the same level.
Description
Every level is completely full. It has the largest possible number of nodes for its height. Every perfect tree is also full, complete and balanced.
Formulas
n = 2h+1 − 1 · leaves = 2h · internal = 2h − 1 · nodes on level l = 2l · h = log2(n + 1) − 1.
How to check
Find the height h and count the nodes n. The tree is perfect exactly when n = 2h+1 − 1. (Equivalently: it is full and all leaves have the same depth.)

4. Skewed binary tree left-skewed or right-skewed

Definition
A binary tree in which every node except the last has only a left child (left-skewed) or only a right child (right-skewed).
Description
The tree is a straight line leaning to one side. A BST becomes skewed when keys are inserted in sorted order, which makes every operation O(n).
Formulas
h = n − 1 (the maximum possible height) · exactly 1 leaf · array storage needs 2n − 1 slots for a right-skewed tree of n nodes (2n−1 for left-skewed), although only n are used.
How to check
Walk down the left links from the root; if any node on the way has a right child, it is not left-skewed. Mirror the test for right-skewed.

5. Degenerate (pathological) binary tree

Definition
A binary tree in which every internal node has exactly one child, on either side.
Description
It behaves like a linked list. A skewed tree is the special case where all the single children are on the same side.
Formulas
h = n − 1 · 1 leaf · n1 = n − 1 nodes with one child · number of different degenerate shapes with n nodes = 2n−1.
How to check
No node may have two children. Equivalently, the height equals n − 1.

6. Balanced (height-balanced) binary tree

Definition
A binary tree in which, for every node, the heights of the left and right subtrees differ by at most 1.
Description
It keeps the height close to log2 n, so search stays fast. AVL trees (Part 6) are balanced BSTs. Complete and perfect trees are always balanced, but a balanced tree need not be complete.
Formulas
|h(left) − h(right)| ≤ 1 at every node · h = O(log n); more precisely h < 1.44 log2(n + 2).
How to check
Compute heights bottom-up (post-order). At each node compare the two subtree heights; if any difference exceeds 1, it is not balanced. Checking only the root is not enough.

7. Extended binary tree also: 2-tree

Definition
The tree obtained by replacing every empty (NULL) subtree with a special external node, usually drawn as a square. The original nodes are called internal nodes.
Description
After extension every internal node has exactly two children, so the result is a full binary tree. It is used to analyse searching: an unsuccessful search in a BST always ends at an external node.
Formulas
External nodes E = I + 1 (I = internal nodes) · external path length Ep = Ip + 2I.
How to check
Count the NULL links of the original tree: there are always n + 1 of them, and each becomes one external node.

C functions to test each type
int isFull(struct node *r) {
    if (r == NULL) return 1;
    if ((r->left == NULL) != (r->right == NULL)) return 0;   /* exactly one child */
    return isFull(r->left) && isFull(r->right);
}

/* call as isComplete(root, 0, countNodes(root)) */
int isComplete(struct node *r, int i, int n) {
    if (r == NULL) return 1;
    if (i >= n) return 0;                /* position beyond n-1: there is a gap */
    return isComplete(r->left, 2 * i + 1, n) && isComplete(r->right, 2 * i + 2, n);
}

int isPerfect(struct node *r) {
    int h = height(r), n = countNodes(r);
    return n == (1 << (h + 1)) - 1;      /* n = 2^(h+1) - 1 */
}

int isLeftSkewed(struct node *r) {
    for (; r != NULL; r = r->left)
        if (r->right != NULL) return 0;
    return 1;
}

int isDegenerate(struct node *r) {
    if (r == NULL) return 1;
    if (r->left != NULL && r->right != NULL) return 0;       /* two children */
    return isDegenerate(r->left) && isDegenerate(r->right);
}

/* returns the height, or -2 as soon as some node is unbalanced */
int checkBalanced(struct node *r) {
    int lh, rh;
    if (r == NULL) return -1;
    lh = checkBalanced(r->left);  if (lh == -2) return -2;
    rh = checkBalanced(r->right); if (rh == -2) return -2;
    if (lh - rh > 1 || rh - lh > 1) return -2;
    return 1 + (lh > rh ? lh : rh);
}

These use countNodes() and height() from section 2.8. Each returns 1 for yes and 0 for no.

2.5Linked implementation

Each node is created dynamically with malloc and holds the data and two pointers. An empty subtree is simply a NULL pointer, and the whole tree is reached through one pointer, root.

struct node {
    int data;
    struct node *left;    /* address of the left child,  NULL if none */
    struct node *right;   /* address of the right child, NULL if none */

struct node *createNode(int x) {
    struct node *n = (struct node *)malloc(sizeof(struct node));
    n->data = x;
    n->left = n->right = NULL;

2.6Traversals

A traversal visits every node exactly once. The three depth-first orders differ only in when the root (N) is printed relative to the left (L) and right (R) subtrees.

TraversalOrderRecursive ruleUsed for
Pre-orderN L Rprint root, pre(left), pre(right)Copying a tree, prefix expression
In-orderL N Rin(left), print root, in(right)Sorted output of a BST, infix expression
Post-orderL R Npost(left), post(right), print rootDeleting or freeing a tree, postfix expression
Level-orderlevel by leveluse a queue (breadth-first)Printing by levels, finding the shallowest node
Quick method on paper: trace a line around the tree counter-clockwise, starting left of the root. Print a node when you pass its left side for pre-order, its bottom for in-order, and its right side for post-order.

Each traversal visits n nodes once: time O(n). Recursion uses stack space equal to the height: O(h), which is O(log n) for a balanced tree and O(n) for a skewed one.

Level-order with a queue

  1. If the root is NULL, stop. Otherwise enqueue the root.
  2. While the queue is not empty: dequeue a node and print it.
  3. Enqueue its left child, then its right child (if they exist).

Recursive vs. non-recursive: side by side

Recursion uses the system's call stack to remember where to come back to. The non-recursive versions do the same job with an explicit stack that we manage ourselves. Both produce exactly the same output (Program 1 below prints both, so you can compare).

Pre-order · N L R

Recursive

void preorder(struct node *r) {
    if (r == NULL) return;
    printf("%d ", r->data);    /* N */
    preorder(r->left);         /* L */
    preorder(r->right);        /* R */
}

Non-recursive (one stack)

void preorderIter(struct node *root) {
    struct node *stack[100], *cur;
    int top = -1;
    if (root == NULL) return;
    stack[++top] = root;
    while (top != -1) {
        cur = stack[top--];        /* pop and visit */
        printf("%d ", cur->data);
        if (cur->right) stack[++top] = cur->right;
        if (cur->left)  stack[++top] = cur->left; /* left on top */
    }
}

Idea: print a node as soon as it is popped. Push the right child before the left child, because a stack is last-in-first-out and the left subtree must come out first.

In-order · L N R

Recursive

void inorder(struct node *r) {
    if (r == NULL) return;
    inorder(r->left);          /* L */
    printf("%d ", r->data);    /* N */
    inorder(r->right);         /* R */
}

Non-recursive (one stack)

void inorderIter(struct node *root) {
    struct node *stack[100], *cur = root;
    int top = -1;
    while (cur != NULL || top != -1) {
        while (cur != NULL) {   /* go left, push path */
            stack[++top] = cur;
            cur = cur->left;
        }
        cur = stack[top--];     /* leftmost unvisited */
        printf("%d ", cur->data);
        cur = cur->right;       /* then right subtree */
    }
}

Idea: keep going left and push every node on the way. When you cannot go further left, pop, print, and then move to the popped node's right child.

Post-order · L R N

Recursive

void postorder(struct node *r) {
    if (r == NULL) return;
    postorder(r->left);        /* L */
    postorder(r->right);       /* R */
    printf("%d ", r->data);    /* N */
}

Non-recursive (two stacks)

void postorderIter(struct node *root) {
    struct node *s1[100], *s2[100], *cur;
    int t1 = -1, t2 = -1;
    if (root == NULL) return;
    s1[++t1] = root;
    while (t1 != -1) {
        cur = s1[t1--];
        s2[++t2] = cur;         /* s2 gets N R L */
        if (cur->left)  s1[++t1] = cur->left;
        if (cur->right) s1[++t1] = cur->right;
    }
    while (t2 != -1)            /* reverse: L R N */
        printf("%d ", s2[t2--]->data);
}

Idea: the first loop produces the order N R L (a mirror pre-order) into stack S2. Popping S2 reverses it, giving L R N.

Pattern 1 · Pre-order + In-order

  1. Take the next unused key from the front of the pre-order. It is the root of the current part.
  2. Find it in the in-order segment. Keys to its left form the left subtree, keys to its right form the right subtree.
  3. Build the left subtree first (recursively, with step 1), then the right subtree. Pre-order is N L R, so its keys are used in exactly this order.
  4. A segment with no keys is an empty subtree (NULL). A segment with one key is a leaf.

2.8Insert, search and delete

A plain binary tree has no ordering rule, so the operations work level by level to keep the tree compact (close to complete).

Insert

Do a level-order walk with a queue. The first node found with an empty left or right slot receives the new node (left is checked first).

Search

Visit nodes in any traversal order until the key is found. Without ordering, every node may have to be checked: O(n).

Delete

Find the target and the deepest, right-most node (the last node in level order). Copy the deepest node's data into the target, then remove the deepest node.

Algorithm BT-INSERT(root, x)                 (level-order insert)
1. If root = NULL, return a new node x.
2. Enqueue root.
3. While the queue is not empty:
      t = dequeue()
      If t.left = NULL:  t.left = new node x;  stop.   Else enqueue t.left.
      If t.right = NULL: t.right = new node x; stop.   Else enqueue t.right.

Algorithm BT-DELETE(root, x)
1. Level-order walk: remember the node T holding x and the last node D visited
   (the deepest, right-most node) and D's parent P.
2. If T was not found, report "not found".
3. T.data = D.data           (copy the deepest node's value into T)
4. Set P's pointer to D to NULL and free D.

  • Binary tree: each node has at most 2 children, and left ≠ right.

Binary Search Tree

A binary tree with an ordering rule, so every comparison lets you skip one whole subtree.

Syllabus: BST: insert, search, delete.

3.1Definition

Definition

A binary search tree is a binary tree that is either empty or satisfies: (i) every key in the left subtree of a node is smaller than the node's key; (ii) every key in the right subtree is larger; (iii) the left and right subtrees are themselves BSTs. Keys are distinct.

The in-order traversal of a BST always gives the keys in ascending order.
Common mistake: Checking only each parent with its two children is not enough. The rule applies to the whole subtree. The in-order test catches this: 20 30 60 50 70 is not sorted.

3.2Search

  1. Start at the root. If it is NULL, the key is not present.
  2. If key = node's key, it is found.
  3. If key < node's key, search the left subtree; otherwise search the right subtree.

Each comparison moves down one level, so search takes at most h + 1 comparisons: O(h).

Recursive

struct node *search(struct node *r, int key) {
    if (r == NULL || r->data == key)
        return r;                  /* NULL = not found */
    if (key < r->data)
        return search(r->left, key);
    return search(r->right, key);
}

Iterative

struct node *search(struct node *r, int key) {
    while (r != NULL && r->data != key) {
        if (key < r->data) r = r->left;
        else               r = r->right;
    }
    return r;                      /* NULL = not found */
}

3.3Insert

Insertion is an unsuccessful search. Search for the key; where the search falls off the tree at a NULL link, attach the new node as a leaf. Existing nodes never move.

Algorithm INSERT(root, key)
1. If root = NULL, create a new node with key, set its left and right to NULL,
   and return it as the root of this subtree.
2. If key < root.data,  root.left  = INSERT(root.left, key)
3. Else if key > root.data, root.right = INSERT(root.right, key)
4. Else the key already exists: do nothing.
5. Return root.
struct node *insert(struct node *root, int x) {
    if (root == NULL) return createNode(x);     /* empty spot found */
    if (x < root->data)      root->left  = insert(root->left, x);
    else if (x > root->data) root->right = insert(root->right, x);
    return root;                                /* duplicates ignored */
}

3.4Delete: three cases

First search for the node. What happens next depends on how many children it has.

CaseAction
1. Leaf (no child)Set the parent's pointer to NULL and free the node.
2. One childLink the parent directly to that child, bypassing the node, then free it.
3. Two childrenFind the in-order successor (smallest key in the right subtree: go right once, then left as far as possible). Copy its key into the node, then delete the successor, which is always Case 1 or Case 2. The in-order predecessor (largest in the left subtree) works equally well.
Algorithm DELETE(root, key)
1. If root = NULL, the key is not present. Return NULL.
2. If key < root.data, root.left  = DELETE(root.left, key); return root.
3. If key > root.data, root.right = DELETE(root.right, key); return root.
4. (key = root.data: this is the node to delete)
   a. If root.left = NULL:  temp = root.right; free(root); return temp.   (cases 1 and 2)
   b. If root.right = NULL: temp = root.left;  free(root); return temp.   (case 2)
   c. Otherwise (case 3): succ = leftmost node of root.right.
      root.data = succ.data
      root.right = DELETE(root.right, succ.data)
5. Return root.
struct node *deleteNode(struct node *root, int key) {
    struct node *temp;
    if (root == NULL) return NULL;                       /* not found */
    if (key < root->data)      root->left  = deleteNode(root->left, key);
    else if (key > root->data) root->right = deleteNode(root->right, key);
    else {
        if (root->left == NULL)  { temp = root->right; free(root); return temp; }
        if (root->right == NULL) { temp = root->left;  free(root); return temp; }
        temp = root->right;                              /* two children:   */
        while (temp->left != NULL) temp = temp->left;    /* find successor  */
        root->data = temp->data;                         /* copy it up      */
        root->right = deleteNode(root->right, temp->data); /* remove old copy */
    }
    return root;
}

3.5Minimum, maximum, successor

  • Minimum: start at the root and keep going left. The last node is the minimum.
  • Maximum: keep going right.
  • In-order successor of a node with a right child: the minimum of its right subtree. Predecessor with a left child: the maximum of its left subtree.

Multiway Tree

Nodes holding several sorted keys and several children. Fewer levels means fewer disk reads, and that is the reason these trees exist.

Syllabus: Multiway trees (m-way search trees).

4.1Why go beyond two children?

When data lives on disk, reading one node costs one disk access, which is thousands of times slower than a comparison in memory. A disk block can hold many keys, so it is better to put many keys in one node and read them all in a single access.

Real-life picture: a dictionary's thumb index. The first "node" has 26 letter tabs (many keys at once). You open the right tab, then a page header shows a range of words, then you scan one page. Three looks instead of halving the book twenty times.
Multiway tree (general)

A multiway tree (m-ary or k-ary tree) is a tree in which a node may have more than two children. When the keys in every node are kept in sorted order and each child holds only the keys that fall between two neighbouring keys of its parent, it is called an m-way search tree. The rest of this part is about m-way search trees.

4.2m-way search tree: definition

Definition

An m-way search tree (search tree of order m) is either empty or satisfies:

  1. Each node has at most m children and at most m − 1 keys.
  2. The keys in a node are in ascending order: K1 < K2 < … < Kk.
  3. A node with k keys has k + 1 child pointers P0 … Pk. All keys in subtree Pi lie between Ki and Ki+1: subtree P0 holds keys < K1, and subtree Pk holds keys > Kk.
  4. Every subtree Pi is itself an m-way search tree.

A BST is simply a 2-way search tree: 1 key and 2 children per node.

Node structure

#define M 4                       /* order */
struct mnode {
    int count;                    /* keys in use, at most M-1 */
    int key[M - 1];
    struct mnode *child[M];       /* child[i]: keys between key[i-1] and key[i] */
};

Example: an m-way search tree of order 3

Each node holds at most 2 keys and 3 pointers. Dots are NULL pointers. Check the rule at the root [35, 60]: the left subtree holds keys < 35 (10, 15, 20, 25), the middle holds keys between 35 and 60 (40, 50), and the right holds keys > 60 (70, 80, 90).

4.3Search

  1. At the current node, scan the keys left to right until you reach the first key ≥ the search key.
  2. If it is equal, the key is found.
  3. Otherwise follow the pointer just before that key (or the last pointer if the key is larger than all of them).
  4. If the pointer is NULL, the key is not in the tree.

Inside a node the scan can be linear or binary search. The number of nodes visited is at most the number of levels.

Algorithm MWAY-SEARCH(node, x)
1. If node = NULL, return "not found".
2. Find the smallest i such that x ≤ node.key[i]   (i = count if x is larger than all keys).
3. If i < count and x = node.key[i], return node   (found).
4. Otherwise return MWAY-SEARCH(node.child[i], x).

4.4Insert

  1. Start at the root and find the pointer range where the key belongs.
  2. If the node has room (fewer than m − 1 keys) and that pointer is NULL, insert the key into this node in sorted position. Done.
  3. Otherwise, if that pointer leads to a subtree, go down and repeat.
  4. If the node is full and the pointer is NULL, create a new node containing only this key and hang it on that pointer.

Worked example: order 3, insert 35, 60, 20, 80, 10, 25, 40, 50, 90, 70, 15

Insertion order decides the shape

The weakness: nothing keeps an m-way search tree balanced. New nodes are opened wherever a key lands, so insertion order can make it tall and lopsided, just like a skewed BST. The B-tree (Part 5) is an m-way search tree with extra rules that keep every leaf on the same level.

4.5Delete

Search for the key Ki. Look at the two pointers on either side of it, Pi−1 (left) and Pi (right):

CaseAction
1. Both side pointers NULLRemove Ki (and one NULL pointer) from the node. If the node becomes empty, delete the node and set its parent's pointer to NULL.
2. Left subtree existsReplace Ki with the largest key in the left subtree (go to Pi−1, then keep taking the last pointer). Then delete that key from the left subtree.
3. Only the right subtree existsReplace Ki with the smallest key in the right subtree (go to Pi, then keep taking the first pointer). Then delete that key from the right subtree.

This is the same idea as Case 3 of BST deletion: a replacement key from just below keeps every range correct.

Worked example: delete 40 (case 1), 35 (case 2), then 10 (case 3)

/* m-way search tree (order M): node structure, search, insert, delete, in-order */
#include <stdio.h>
#include <stdlib.h>
#define M 3                      /* order: at most M children, M-1 keys */

struct mnode {
    int count;                   /* number of keys in use */
    int key[M - 1];              /* key[0] < key[1] < ... */
    struct mnode *child[M];      /* child[i] holds keys between key[i-1] and key[i] */
};

struct mnode *newNode(int x) {
    int i;
    struct mnode *n = (struct mnode *)malloc(sizeof(struct mnode));
    n->count = 1;
    n->key[0] = x;
    for (i = 0; i < M; i++) n->child[i] = NULL;
    return n;
}

/* position of the first key >= x inside one node */
int slot(struct mnode *n, int x) {
    int i = 0;
    while (i < n->count && x > n->key[i]) i++;
    return i;
}

struct mnode *search(struct mnode *root, int x) {
    int i;
    while (root != NULL) {
        i = slot(root, x);
        if (i < root->count && root->key[i] == x) return root;
        root = root->child[i];   /* one pointer per gap between keys */
    }
    return NULL;
}

/* fill a node up to M-1 keys; otherwise go down (creating a new child if needed) */
struct mnode *insert(struct mnode *root, int x) {
    struct mnode *n = root;
    int i, j;
    if (root == NULL) return newNode(x);
    while (1) {
        i = slot(n, x);
        if (i < n->count && n->key[i] == x) return root;          /* duplicate */
        if (n->count < M - 1 && n->child[i] == NULL) {            /* room here */
            for (j = n->count; j > i; j--) {
                n->key[j] = n->key[j - 1];
                n->child[j + 1] = n->child[j];
            }
            n->key[i] = x;
            n->child[i + 1] = NULL;
            n->count++;
            return root;
        }
        if (n->child[i] == NULL) { n->child[i] = newNode(x); return root; }
        n = n->child[i];
    }
}

/* delete x from the subtree rooted at n; returns the (possibly NULL) new subtree root */
struct mnode *deleteKey(struct mnode *n, int x) {
    int i, j, rep;
    struct mnode *t;
    if (n == NULL) { printf("%d not found\n", x); return NULL; }
    i = slot(n, x);
    if (i == n->count || n->key[i] != x) {         /* not in this node: go down */
        n->child[i] = deleteKey(n->child[i], x);
        return n;
    }
    if (n->child[i] == NULL && n->child[i + 1] == NULL) {   /* both side pointers NULL */
        for (j = i; j < n->count - 1; j++) {
            n->key[j] = n->key[j + 1];
            n->child[j + 1] = n->child[j + 2];
        }
        n->child[n->count] = NULL;
        n->count--;
        if (n->count == 0) { free(n); return NULL; }    /* node became empty */
        return n;
    }
    if (n->child[i] != NULL) {                     /* replace by largest key on the left */
        t = n->child[i];
        while (t->child[t->count] != NULL) t = t->child[t->count];
        rep = t->key[t->count - 1];
        n->key[i] = rep;
        n->child[i] = deleteKey(n->child[i], rep);
    } else {                                       /* replace by smallest key on the right */
        t = n->child[i + 1];
        while (t->child[0] != NULL) t = t->child[0];
        rep = t->key[0];
        n->key[i] = rep;
        n->child[i + 1] = deleteKey(n->child[i + 1], rep);
    }
    return n;
}

Key points to remember

  • An m-way search tree node has up to m children and m − 1 sorted keys.
  • Keys in child Pi lie between Ki and Ki+1; a BST is a 2-way search tree.
  • Fat nodes mean fewer levels, and each level is one disk read.
  • Insert fills a node up to m − 1 keys, then opens a new child. Nothing keeps it balanced.
  • Delete: remove directly if both side pointers are NULL; otherwise replace by the largest key on the left (or smallest on the right).
  • Max keys in an m-way tree of height h: mh+1 − 1.

B-Tree and B+ Tree

A B-tree is a balanced m-way search tree: it grows and shrinks at the root, so every leaf stays on the same level. A B+ tree keeps all data in linked leaves, which is what databases use.

Syllabus: B-Trees. (B+ tree, sections 5.7–5.11, is included because it is asked alongside B-trees.)

5.1Why B-trees, and the definition

An m-way search tree has fat nodes (good for disks) but can become lopsided (bad). A B-tree adds two balance rules: every node except the root must be at least half full, and all leaves must be on the same level. It was introduced by Bayer and McCreight (1972) for disk-based indexes.

Definition

A B-tree of order m is an m-way search tree that is either empty or satisfies:

  1. Every node has at most m children and at most m − 1 keys.
  2. Every internal node except the root has at least ⌈m/2⌉ children, and every node except the root has at least ⌈m/2⌉ − 1 keys.
  3. The root has at least 2 children unless it is a leaf (it can hold as few as 1 key).
  4. All leaves are on the same level.
  5. A non-leaf node with k keys has exactly k + 1 children.

Order means maximum children, not keys. Some books define order as the minimum degree t (Cormen), where a node has between t − 1 and 2t − 1 keys. If a question says "B-tree of order 5", use m = 5: at most 4 keys per node.

5.2Search

Exactly the m-way search: scan the keys in the node, stop if found, otherwise follow the pointer for the key's range. Because all leaves are on one level, a search reads at most h + 1 nodes, and h is O(log⌈m/2⌉ n).

Algorithm B-TREE-SEARCH(node, x)
1. i = 0
2. While i < node.n and x > node.key[i]:  i = i + 1
3. If i < node.n and x = node.key[i]:  return (node, i)      found
4. If node is a leaf:  return NULL                             not found
5. Return B-TREE-SEARCH(node.child[i], x)

5.3Insert: always into a leaf, split on overflow

  1. Search down to the leaf where the key belongs. New keys are never placed directly in an internal node.
  2. Insert the key in sorted order inside that leaf.
  3. If the leaf now has m keys (overflow), split it: the median key moves up into the parent, the keys to its left form one node and the keys to its right form another.
  4. If the parent overflows because of the key it received, split the parent the same way. Repeat upward.
  5. If the root splits, the median becomes a new root. This is the only way the height grows, which is why all leaves stay on one level.
Algorithm B-TREE-INSERT(root, key)
1. If the tree is empty, create a root node containing key. Stop.
2. Starting at the root, move down: in each node find the child whose range
   contains key, until a leaf L is reached.
3. Insert key into L in sorted order.
4. While the current node has m keys (overflow):
   a. Take the median key K (position ⌈m/2⌉).
   b. Split the node into Left (keys before K) and Right (keys after K).
   c. If the node is the root: make a new root containing only K,
      with children Left and Right. Stop (height grows by 1).
   d. Otherwise insert K into the parent (with Right as its new child)
      and move up to the parent.

For even m the overflowing node has an even number of keys, so there are two middle keys. These notes send the left-middle key up (position ⌈m/2⌉). Some books use the right-middle; either is correct if you use it consistently.

1. Search for x. If x is in an internal node, replace it with its in-order
   successor (or predecessor), which is in a leaf, and delete that key instead.
2. Remove the key from the leaf L.
3. While L is not the root and L has fewer than ⌈m/2⌉ − 1 keys:
   a. If a neighbouring sibling S has more than the minimum:
        move the separator from the parent down into L,
        move S's nearest key up into the parent       (borrow). Stop.
   b. Else merge L, the separator and S into one node;
        remove the separator from the parent; L = parent   (merge, repeat).
4. If the root has no keys left, make its only child the new root.

5.5Height and complexity

A B-tree of order m with n keys has height h ≤ log⌈m/2⌉((n + 1) / 2).

The root has at least 2 children and every other internal node at least ⌈m/2⌉, so the number of keys grows exponentially with the height. For m = 200 and n = 2 million keys, h ≤ log100(1,000,000) = 3. Any key is at most 4 disk reads away.

5.7B+ tree: definition and structure

Definition

A B+ tree of order m is a balanced multiway tree in which all data keys are stored in the leaves, the internal nodes store only copies of keys that guide the search, and the leaves are linked together in key order. Like a B-tree, all leaves are on the same level and every non-root node is at least half full.

Index set (internal nodes)

At most m children and m − 1 keys. Keys are signposts only: all keys in child Pi are ≥ Ki and < Ki+1.

Sequence set (leaves)

Hold every key (and the record or record pointer). Each leaf has a next pointer to the leaf on its right, forming a sorted linked list.

#define M 4
struct bpnode {
    int isLeaf;
    int n;                        /* keys in use (at most M-1)          */
    int key[M - 1];
    struct bpnode *child[M];      /* used only in internal nodes         */
    struct bpnode *next;          /* used only in leaves: next leaf      */
};

5.8B+ tree: search and range query

  1. At an index node, find the first key greater than x and follow the pointer before it. If x equals a key, go to its right (keys ≥ Ki live on the right).
  2. Repeat until a leaf is reached. The search always ends at a leaf, even if x was seen in an index node.
  3. Range query lo…hi: search for lo, then walk along the leaf links collecting keys until a key > hi appears. No need to go back up the tree.

/* B-Tree of order M: search, insert (split at median), delete (borrow / merge), traversal */
#include <stdio.h>
#include <stdlib.h>
#define M 3                         /* order: max M children, max M-1 keys        */
#define MIN ((M + 1) / 2 - 1)       /* min keys in a non-root node = ceil(M/2) - 1 */

struct bnode {
    int n;                          /* keys in use                                 */
    int key[M];                     /* one extra slot to hold a temporary overflow */
    struct bnode *child[M + 1];
    int leaf;
};

struct bnode *root = NULL;

struct bnode *newNode(int leaf) {
    int i;
    struct bnode *t = (struct bnode *)malloc(sizeof(struct bnode));
    t->n = 0; t->leaf = leaf;
    for (i = 0; i <= M; i++) t->child[i] = NULL;
    return t;
}

int slot(struct bnode *t, int x) { int i = 0; while (i < t->n && x > t->key[i]) i++; return i; }

struct bnode *search(struct bnode *t, int x) {
    int i;
    while (t) {
        i = slot(t, x);
        if (i < t->n && t->key[i] == x) return t;
        if (t->leaf) return NULL;
        t = t->child[i];
    }
    return NULL;
}

/* split overflowing child c = p->child[i] (it holds M keys) around its median */
void splitChild(struct bnode *p, int i) {
    struct bnode *c = p->child[i], *r = newNode(c->leaf);
    int mid = (M + 1) / 2 - 1, j;             /* median index = ceil(M/2) - 1 */
    r->n = c->n - mid - 1;
    for (j = 0; j < r->n; j++) r->key[j] = c->key[mid + 1 + j];
    if (!c->leaf) for (j = 0; j <= r->n; j++) r->child[j] = c->child[mid + 1 + j];
    for (j = p->n; j > i; j--) { p->key[j] = p->key[j - 1]; p->child[j + 1] = p->child[j]; }
    p->key[i] = c->key[mid];                  /* median moves up */
    p->child[i + 1] = r;
    p->n++;
    c->n = mid;
}

/* insert into subtree t; the caller splits t if it overflows */
void insertRec(struct bnode *t, int x) {
    int i = slot(t, x), j;
    if (i < t->n && t->key[i] == x) return;   /* duplicate */
    if (t->leaf) {
        for (j = t->n; j > i; j--) t->key[j] = t->key[j - 1];
        t->key[i] = x; t->n++;
        return;
    }
    insertRec(t->child[i], x);
    if (t->child[i]->n == M) splitChild(t, i);
}

void insert(int x) {
    struct bnode *s;
    if (root == NULL) { root = newNode(1); root->key[0] = x; root->n = 1; return; }
    insertRec(root, x);
    if (root->n == M) {                       /* root overflow: tree grows at the top */
        s = newNode(0); s->child[0] = root; root = s;
        splitChild(s, 0);
    }
}

/* ---------- delete ---------- */
void removeAt(struct bnode *t, int i) {       /* remove key i and child i+1 */
    int j;
    for (j = i; j < t->n - 1; j++) { t->key[j] = t->key[j + 1]; t->child[j + 1] = t->child[j + 2]; }
    t->n--;
}

/* child p->child[i] has MIN-1 keys: borrow from a sibling or merge */
void fix(struct bnode *p, int i) {
    struct bnode *c = p->child[i], *L, *R;
    int j;
    L = (i > 0) ? p->child[i - 1] : NULL;
    R = (i < p->n) ? p->child[i + 1] : NULL;
    if (L && L->n > MIN) {                    /* borrow from left */
        for (j = c->n; j > 0; j--) c->key[j] = c->key[j - 1];
        if (!c->leaf) for (j = c->n + 1; j > 0; j--) c->child[j] = c->child[j - 1];
        c->key[0] = p->key[i - 1];
        if (!c->leaf) c->child[0] = L->child[L->n];
        p->key[i - 1] = L->key[L->n - 1];
        L->n--; c->n++;
    } else if (R && R->n > MIN) {             /* borrow from right */
        c->key[c->n] = p->key[i];
        if (!c->leaf) c->child[c->n + 1] = R->child[0];
        c->n++;
        p->key[i] = R->key[0];
        for (j = 0; j < R->n - 1; j++) R->key[j] = R->key[j + 1];
        if (!R->leaf) for (j = 0; j < R->n; j++) R->child[j] = R->child[j + 1];
        R->n--;
    } else {                                  /* merge with a sibling */
        if (L) { c = L; R = p->child[i]; i--; }  /* merge child[i] and child[i+1] */
        c->key[c->n] = p->key[i];
        for (j = 0; j < R->n; j++) c->key[c->n + 1 + j] = R->key[j];
        if (!c->leaf) for (j = 0; j <= R->n; j++) c->child[c->n + 1 + j] = R->child[j];
        c->n += R->n + 1;
        free(R);
        removeAt(p, i);
    }

void deleteRec(struct bnode *t, int x) {
    int i = slot(t, x);
    struct bnode *s;
    if (i < t->n && t->key[i] == x) {
        if (t->leaf) { for (; i < t->n - 1; i++) t->key[i] = t->key[i + 1]; t->n--; return; }
        s = t->child[i + 1];                  /* internal: use the in-order successor */
        while (!s->leaf) s = s->child[0];
        t->key[i] = s->key[0];
        x = s->key[0];
        i = i + 1;                            /* now delete the successor from the right subtree */
    } else if (t->leaf) { printf("%d not found\n", x); return; }
    deleteRec(t->child[i], x);
    if (t->child[i]->n < MIN) fix(t, i);
}

void deleteKey(int x) {
    struct bnode *old;
    if (root == NULL) return;
    deleteRec(root, x);
    if (root->n == 0) {                       /* root emptied: tree shrinks */
        old = root;
        root = root->leaf ? NULL : root->child[0];
        free(old);
    }
}

Key points to remember

  • B-tree of order m: max m children and m − 1 keys; min ⌈m/2⌉ children (internal, non-root) and ⌈m/2⌉ − 1 keys (non-root).
  • All leaves on one level, always.
  • Insert into a leaf; on overflow split and push the median up. Only a root split increases the height.
  • Delete: from a leaf directly, or replace an internal key by its successor. On underflow borrow from a sibling if it can spare a key, otherwise merge.
  • Height is O(log⌈m/2⌉ n), so a lookup needs only a few disk reads.
  • B+ tree: all data in linked leaves, index nodes hold copies. Leaf split copies the key up; index split moves it up. Every search ends at a leaf; range queries walk the leaf chain.

Unit IV · Part 6

AVL Tree

A BST that checks its balance after every insert and delete, and repairs it with rotations, so the height never goes beyond about 1.44 log2 n.

Syllabus: AVL tree · single rotations · double rotations.

6.1Definition and balance factor

Definition

An AVL tree (Adelson-Velsky and Landis, 1962) is a binary search tree in which, for every node, the heights of the left and right subtrees differ by at most 1.

Balance factor BF(node) = height(left subtree) − height(right subtree). In an AVL tree every BF is −1, 0 or +1.

BF = +1 means left-heavy, −1 means right-heavy, 0 means equal. An empty subtree has height −1, so a leaf has BF = 0. In the figures, the small number beside each node is its BF.

How to calculate BF (left tree above)

Work bottom-up: find each subtree's height first (leaf = 0, empty = −1), then subtract.

6.2Why AVL?

A plain BST becomes a linked list when keys arrive in sorted order, and every operation drops to O(n). An AVL tree restores balance locally after each change. The cost is a few pointer changes, and in return search, insert and delete are all guaranteed O(log n).

6.3Rotations

A rotation rearranges three nodes (z = the unbalanced node, y = its taller child, x = y's taller child) and their subtrees T1–T4. It keeps the BST order (the in-order sequence of the nodes and subtrees does not change: in the LL picture below it is T1 10 T2 20 T3 30 T4 before and after) and reduces the height of that part of the tree by one.

Name the case by the path from the unbalanced node down to where the extra height is: two steps Left = LL, Left then Right = LR, and so on.

Single rotations

LL case: the new node went into the left subtree of the left child. Fix: one right rotation at z.
RR case: the new node went into the right subtree of the right child. Fix: one left rotation at z.
struct node *rightRotate(struct node *y) {   /* LL */
    struct node *x = y->left, *T2 = x->right;
    x->right = y;          /* y comes down to the right of x   */
    y->left = T2;          /* x's old right subtree moves to y */
    update(y); update(x);  /* recompute heights, lower node first */
    return x;              /* x is the new root of this subtree */
}

struct node *leftRotate(struct node *x) {    /* RR */
    struct node *y = x->right, *T2 = y->left;
    y->left = x;
    x->right = T2;
    update(x); update(y);
    return y;
}

Double rotations

If the extra height is on the inside (a zig-zag), one rotation only moves the problem to the other side. First rotate at the child to make a straight line, then rotate at z.

LR case: the new node went into the right subtree of the left child. Fix: left rotation at y, then right rotation at z.
RL case: the new node went into the left subtree of the right child. Fix: right rotation at y, then left rotation at z.

6.4Insertion

  1. Insert the key exactly as in a BST (it becomes a leaf).
  2. Walk back up the path towards the root, updating heights and balance factors.
  3. At the first node whose BF becomes ±2, identify the case (LL, RR, LR or RL) and apply the rotation.
  4. After one rotation (single or double) the subtree is back to its old height, so no other ancestor needs fixing. An insertion needs at most one rotation.
Algorithm AVL-INSERT(node, key)
1. If node = NULL, return a new node (height 0).
2. If key < node.data, node.left  = AVL-INSERT(node.left, key)
   Else if key > node.data, node.right = AVL-INSERT(node.right, key)
   Else return node (duplicate).
3. Update node.height = 1 + max(height(left), height(right)).
4. BF = height(left) − height(right).
5. If BF = +2 and BF(node.left) ≥ 0  : return RIGHT-ROTATE(node)            (LL)
   If BF = +2 and BF(node.left) < 0  : node.left = LEFT-ROTATE(node.left);
                                        return RIGHT-ROTATE(node)            (LR)
   If BF = −2 and BF(node.right) ≤ 0 : return LEFT-ROTATE(node)             (RR)
   If BF = −2 and BF(node.right) > 0 : node.right = RIGHT-ROTATE(node.right);

6. Return node.

6.5Deletion

  1. Delete as in a BST (the two-children case uses the in-order successor).
  2. Walk up from the parent of the node that was physically removed, updating heights.
  3. At every node with BF ±2, look at the child on the taller side (the sibling of the side that got shorter) and use the same identification table. When that child's BF is 0, a single rotation is used (this case never happens during insertion).
  4. A rotation after deletion can make the subtree shorter, which can unbalance a higher ancestor. Keep checking all the way to the root. A deletion may need up to O(log n) rotations.

Many textbooks name the deletion cases R0, R1, R−1 (deleted from the right side) and L0, L1, L−1 (deleted from the left side). The number is the BF of the sibling node on the other side.

6.6Height bound and complexity

7.2Binary heap (min-heap and max-heap)

Definition

A binary heap is a complete binary tree that satisfies the heap order property: in a max-heap every node is ≥ its children (so the maximum is at the root); in a min-heap every node is ≤ its children (the minimum is at the root).

Because it is complete, a heap is stored in an array with no gaps: children of index i are at 2i + 1 and 2i + 2, the parent at ⌊(i − 1)/2⌋. Unlike a BST, there is no order between siblings, so a heap is not good for searching an arbitrary key; it is good for always getting the largest (or smallest) quickly.

7.3Threaded binary tree

Definition

A threaded binary tree is a binary tree in which every NULL left pointer is replaced by a pointer to the node's in-order predecessor, and every NULL right pointer by a pointer to its in-order successor. These extra pointers are called threads. Two flag bits in each node tell whether a pointer is a real child link or a thread.

Why: a linked binary tree with n nodes wastes n + 1 NULL pointers (2.3). Threads put them to use, so in-order traversal needs no stack and no recursion.

7.4Red-black tree

Definition

A red-black tree is a binary search tree in which every node is coloured red or black and:

  1. Every node is either red or black.
  2. The root is black.
  3. Every leaf (NULL) is considered black.
  4. A red node cannot have a red child (no two reds in a row).
  5. Every path from a node down to its NULL leaves contains the same number of black nodes (the black-height).

These rules guarantee that the longest root-to-leaf path is at most twice the shortest, so the height is at most 2 log2(n + 1). The balance is looser than AVL, so it needs fewer rotations on updates.

7.5Splay tree

Definition

A splay tree is a self-adjusting binary search tree: after every search, insert or delete, the accessed node is moved to the root by a sequence of rotations called splaying. It stores no balance information.

Frequently used keys stay near the top, so repeated accesses are fast. A single operation can take O(n), but any sequence of m operations takes O(m log n): amortised O(log n) per operation.

The three splay steps (x = accessed node, p = parent, g = grandparent)

Zig p is the root

One rotation at p brings x to the root.

Zig-zig x and p are both left (or both right) children

Rotate at g first, then at p. (This order is what makes splay trees efficient.)

Zig-zag x is a right child and p a left child (or the mirror)

Rotate at p first, then at g, exactly like an AVL double rotation.

Used in: caches, memory allocators, network routers, and anywhere recently used items are likely to be used again.

7.62-3 tree and 2-3-4 tree

Definition

A 2-3 tree is a B-tree of order 3: every internal node is a 2-node (1 key, 2 children) or a 3-node (2 keys, 3 children), and all leaves are on the same level. A 2-3-4 tree is a B-tree of order 4, which also allows 4-nodes (3 keys, 4 children).

Insertion and deletion are exactly the B-tree algorithms of Part 5. A 2-3-4 tree is equivalent to a red-black tree: each 3-node or 4-node corresponds to a black node with one or two red children.

7.7B* tree

Definition

A B* tree is a B-tree in which every non-root node is at least two-thirds full instead of half full.

  • When a node overflows, it first tries to shift keys to a sibling (redistribution) instead of splitting.
  • Only when the sibling is also full are the two full nodes split into three nodes, each about 2/3 full (a 2-to-3 split).
  • Result: better space use (about 66–100% full instead of 50–100%) and a slightly shorter tree, at the cost of more complex insertion.

7.8Trie (prefix tree, digital search tree)

Definition

A trie is a multiway tree for storing strings in which each edge represents one character, the path from the root to a node spells a prefix, and a marked node shows that a complete word ends there. The root represents the empty string.

7.9Huffman tree

Definition

A Huffman tree is a full binary tree whose leaves are the characters of a message, built so that the weighted path length Σ (frequency × depth) is as small as possible. Reading the path from the root (left = 0, right = 1) gives each character's Huffman code, a variable-length prefix code: frequent characters get short codes.

  1. Make a single-node tree for every character, with its frequency as weight.
  2. Pick the two trees with the smallest weights.
  3. Join them under a new root whose weight is their sum (smaller on the left).
  4. Repeat steps 2–3 until one tree is left. With n characters this takes n − 1 merges.

Example: A = 5, B = 9, C = 12, D = 13, E = 16, F = 45

No code is a prefix of another (every character is a leaf), so a bit string can be decoded without separators. Used in: ZIP/DEFLATE, JPEG, MP3 compression.

R.3Common mistakes to avoid

  • Not stating the convention. Write "root at level 0, height in edges" (or your book's version) before any numerical answer.
  • BST check done only locally. Verify with the in-order sequence; it must be sorted.
  • Two-children BST delete done wrongly. The successor is the left-most node of the right subtree, not simply the right child.
  • AVL rotation done at the wrong node. Rotate at the lowest ancestor with BF ±2, not at the root.
  • LR/RL fixed with one rotation. A zig-zag always needs two.
  • Showing only the final tree. Examiners check every intermediate step. Draw the tree after every rotation or split and label it ("RR at 10", "split, 20 moves up").
  • B-tree keys inserted into an internal node. New keys always go into a leaf; only medians move up.
  • B-tree order confused with keys. Order 5 means at most 5 children and 4 keys.
  • AVL deletion stopped after the first rotation. Unlike insertion, deletion must keep checking every ancestor up to the root.
  • B+ leaf split done like a B-tree. In a leaf split the key is copied up and stays in the right leaf; only index splits move the key up.
  • Heap treated like a BST. A heap only orders parent and child; siblings have no order, and in-order does not give sorted output.
  • Pre-order + post-order used to rebuild a tree. The result is not unique; in-order is needed.

Q1Define: complete binary tree, full binary tree, degree of a tree, height of a node, forest.
  • Complete binary tree: every level is completely filled except possibly the last, and the last level's nodes are as far left as possible.
  • Full (strict) binary tree: every node has either 0 or 2 children.
  • Degree of a tree: the maximum degree (number of children) of any node in the tree.
  • Height of a node: the number of edges on the longest path from that node down to a leaf.
  • Forest: a set of n ≥ 0 disjoint trees. Removing the root of a tree gives a forest of its subtrees.

Q9Construct an m-way search tree of order 3 by inserting 35, 60, 20, 80, 10, 25, 40, 50, 90, 70, 15. Then delete 40, 35 and 10.

Order 3: at most 2 keys and 3 pointers per node. A key goes into a node only if the node has room and the pointer for its range is NULL; otherwise it goes down or opens a new node.

  • After all insertions: root [35 60]; children [10 20], [40 50], [80 90]; [15] and [25] hang below [10 20], [70] below [80 90].
  • Delete 40: both pointers beside it are NULL, so remove it directly → [50].
  • Delete 35: its left subtree exists, so replace it with the largest key there, 25 → root [25 60].
  • Delete 10: left pointer NULL, right subtree [15] exists, so replace it with the smallest key there, 15 → [15 20].

Q11From the order-5 B-tree of Q10, delete 8, 20, 18 and 5 in that order. Name the case used each time.

Order 5: every non-root node must keep at least ⌈5/2⌉ − 1 = 2 keys.

  • Delete 8 (leaf, spare keys): leaf [8 11 12] becomes [11 12]. Nothing else changes.
  • Delete 20 (internal key): replace it with its in-order successor 23, then remove 23 from leaf [23 24 25 26], which keeps 3 keys. Parent becomes [17 23].
  • Delete 18 (underflow, borrow): leaf [18 19] becomes [19]. The left sibling [14 16] cannot lend, but the right sibling [24 25 26] can: separator 23 comes down, 24 goes up. Parent [17 24], leaves [19 23] [25 26].
  • Delete 5 (underflow, merge twice, root shrinks): leaf [5 6] becomes [6]. Neither sibling can lend, so merge [1 3] + 4 + [6] = [1 3 4 6]. The parent [4 7] drops to [7] and underflows; its sibling [17 24] cannot lend, so merge [7] + 13 + [17 24] = [7 13 17 24]. The root is now empty and the tree becomes one level shorter.

Final tree: root [7 13 17 24]; leaves [1 3 4 6] [11 12] [14 16] [19 23] [25 26].

Q12Construct a B+ tree of order 4 by inserting 1, 4, 7, 10, 17, 21, 31, 25, 19, 20, 28, 42.

Order 4: at most 3 keys per node. A leaf that gets a 4th key splits: the left leaf keeps 2 keys, and the first key of the right leaf is copied up. An index node that overflows splits like a B-tree: its median moves up.

Final tree: root [17]; index nodes [7] and [20 25 31]; leaf chain [1 4] → [7 10] → [17 19] → [20 21] → [25 28] → [31 42].
